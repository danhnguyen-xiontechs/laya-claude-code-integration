Where to start: BLOCKED vs FAIL is decided in the integration-verifier skill, mainly in scripts/verify.mjs.

Mechanism (read directly, lines are in verify.mjs unless noted):
- deterministicCategory (l.41-47) labels a failed check "environment" when the exit code is 127 or 9009, or the output matches ENV_RX (ECONNREFUSED, EACCES, "command not found", "no space left", etc.).
- combined() (l.208-216) gives each combined required check: PASS if exit 0; BLOCKED if the category is environment; otherwise FAIL.
- finalize() (l.285-295) applies a failure cluster: environment means BLOCKED for the stories it is attributed to; every other story gets at least REVIEW_REQUIRED, so a red combined run never leaves a story PASS.
- BLOCKED is also used for missing evidence, not FAIL: a required check with no log or no exit code (l.118-120), a worktree failure (l.196), no required checks defined (l.343), and no combined check ran (l.297-298).
- FAIL is for real code/conflict failures: a non-environment check exit, a merge conflict (l.207, 283), shared fixtures or contract/config/migration conflicts (l.162-187), and a claimed-failed AC.
- Jev is shadow only (l.250-273; SKILL.md l.56-63). Its suggestion is logged and never changes a status.

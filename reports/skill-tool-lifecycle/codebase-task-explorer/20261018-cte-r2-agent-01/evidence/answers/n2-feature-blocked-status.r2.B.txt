Answer: The BLOCKED-vs-FAIL decision lives in the integration-verifier skill. Story statuses are set deterministically in verify.mjs. BLOCKED means evidence is missing or the environment is at fault. FAIL means a check ran and was red. Jev never changes a status.

Rules as implemented:
- Story level (verifyStory): branch not found, git diff failure, invalid or missing manifest, a required check with no record, no log file or empty log, or no numeric exit code give BLOCKED. A required check with a non-zero exit gives FAIL, with no environment-signature check.
- Combined run (combined): each required check runs in a temporary merged worktree. Exit 0 is PASS. Otherwise, if deterministicCategory matches (exit 127/9009, or ENV_RX such as ECONNREFUSED, EACCES, permission denied, ETIMEDOUT), the check is BLOCKED. Anything else is FAIL.
- finalize: an environment cluster BLOCKs the attributed stories and sets every other story to at least BLOCKED. A code cluster FAILs the attributed stories and sets the others to REVIEW_REQUIRED. No combined checks run gives BLOCKED.

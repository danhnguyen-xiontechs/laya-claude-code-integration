BLOCKED vs FAIL is decided by one rule. A failing combined check is BLOCKED when its output or exit code matches an environment signature (ECONNREFUSED, EACCES, "command not found", exit 127/9009, and similar). Any other non-zero exit is FAIL. A missing check record, missing or empty log, or missing exit code is also BLOCKED. Jev only adds a shadow suggestion and never changes the category, so it cannot move a status.

Things noticed from reading the code (not run):
- Story-reported checks are never classified. verifyStory line 121 gives FAIL for any non-zero exit, even if the log shows ECONNREFUSED. The BLOCKED rule applies only to the combined run, which matches SKILL.md but may not be the intent.
- The environment regex runs over the whole output, so a genuine test failure whose log contains "permission denied" or "connection refused" becomes BLOCKED. That is a false BLOCKED, not a false PASS.
- On timeout, sh() appends the spawn error text, which contains ETIMEDOUT (in ENV_RX). A timed-out combined check is therefore probably BLOCKED, not FAIL. Inferred from the code, untested.

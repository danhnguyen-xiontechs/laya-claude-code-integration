BLOCKED vs FAIL is decided by deterministic rules in integration-verifier's verify.mjs. Jev and the agents' own claims cannot set it.

How it decides:
- Story level (verifyStory, verify.mjs L95-124): BLOCKED if the branch is missing, the manifest is invalid, or a required check has no record, no non-empty log, or no numeric exit code. A recorded non-zero exit on the story's own check is FAIL (L121), with no environment classification.
- Combined run (L208-217): exit 0 is PASS. Non-zero is BLOCKED only if deterministicCategory() returns 'environment' (L41-47: exit 127 or 9009, or ENV_RX matched against the whole output). Otherwise FAIL.
- finalize (L276-301): an environment cluster marks every story BLOCKED. A code cluster marks attributed stories FAIL and the rest REVIEW_REQUIRED. Jev (triage, L250-273) only fills a shadow field and never sets the category.
- Batch-level BLOCKED also comes from no required checks (L343), no combined check run (L298), or a failed worktree add (L196). Worst status wins: FAIL > BLOCKED > REVIEW_REQUIRED > PASS.

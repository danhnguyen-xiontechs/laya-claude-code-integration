Caveats (7)
  • Not the real hook: subagents share this session's hooks, so both arms run tests through the same run.mjs; A returns raw output, B runs it through smart-context-trimming/hooks/trim-core.ts decideAndBuild (same code the hook uses, Jev live). The hook's deny-shape for failed commands is not reproduced.
  • node --test failure lines start with ✖, which trim-core does not match (failedTest regex has ✕ × ✗ but not ✖): js-one-bug, js-three-bugs and js-feature passed through untrimmed, so their A/B token differences are pure noise (−1% … +17%).
  • Noise floor: on untrimmed tasks the same prompt varies up to ±17% between arms and up to ±50% between reps (js-root-exception A: 573k vs 873k), so only dotnet-build (−25% and −36%) is a clear effect.
  • Tokens include cache reads (~85% of all tokens, billed at ~10% of input); the first rep pays more cache writes (cold cache) in both arms.
  • js-root-exception: Jev chose errors_only, but the trimmed output was still 51 KB of 74 KB (40 near-identical stack traces kept), so little was saved.
  • B is slower in wall time (+5–8 s per trimmed run): the Jev call plus the Node fetch keep-alive before run.mjs exits.
  • Synthetic tasks with obvious bugs (made by make_tasks.mjs); 2 reps; one model (haiku, effort xhigh). Some agents briefly wrote scratch files outside their folder and deleted them; grading re-ran the raw command and checked protected files were unchanged.

Agent review (8 findings, 3 open Critical/Major)
  • Major The EXCLUDE pattern `>\s*\S` also matches the stderr redirect `2>&1`, so very common commands such as `dotnet test 2>&1` or `npm test 2>&1` are never classified or trimmed. hooks/trim-core.ts:60 · open
  • Major In the default observe mode, the full raw output of every eligible Bash call is written to ~/.claude/smart-context-trimming/raw without redaction. The TTL only empties files at the next session start, so secrets can stay on disk indefinitely. hooks/register.ts:85 · open
  • Major bench.ts measures reduction and lostCritical on the same hand-written FIXTURES that core.spec.ts uses to check the rules, so 0 lost and 89-91% reduction are in-sample numbers, not evidence on real logs. scripts/bench.ts:8 · open
  • Minor When a Jev decision is accepted, applyJev rebuilds the keep-set from mandatory candidates only, so the warning groups the rules kept are dropped under errors_only. This contradicts the claim that a bad Jev decision can only make the output longer. hooks/trim-core.ts:288 · open
  • Minor The live bench rests on only 3 Jev calls, so medianJevReduction 0.911 vs rule 0.894 is not a meaningful comparison. reports/bench.json:4 · open
  • Minor The timeout uses Promise.race without aborting the request, so a timed-out Jev fetch keeps running, and the sleep timer is never cleared after a fast response. hooks/trim-core.ts:344 · open
  • Minor The raw-save threshold uses text.length (UTF-16 chars) while planTrim uses byteLen, so multi-byte output can be trimmed with no saved raw file, or saved but never trimmed. hooks/register.ts:85 · open
  • Suggestion The 40+ hex redaction also removes git SHAs and content hashes from Jev candidates; safe but loses diagnostic context. hooks/trim-core.ts:197 · open
